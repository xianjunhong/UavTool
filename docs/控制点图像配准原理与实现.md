# 控制点图像配准原理与实现

本文说明 UavTool 中“控制点图像配准”功能解决的问题、仿射变换公式的直观含义、GeoTIFF 地理坐标的写入方式，以及配准结果的金字塔构建逻辑。

## 1. 配准到底在做什么

图像配准可以理解为：将两张描绘同一区域的透明胶片叠在一起，移动、旋转、缩放或适当倾斜其中一张，使道路、建筑物、田块边界等相同地物尽量重合。

在本项目中：

- `src` 是参考影像，其地理位置作为最终基准。
- `target` 是待校正影像。
- 控制点是在两张影像中人工选择的同名位置，例如同一个道路交叉口或同一栋建筑物的角点。

假设某个地物在两张图中的像素位置分别为：

| 影像 | 像素横坐标 | 像素纵坐标 |
| --- | ---: | ---: |
| target | 120 | 80 |
| src | 100 | 70 |

这对控制点表达的含义是：

> target 中的像素 `(120, 80)` 应该对应到 src 中的像素 `(100, 70)`。

程序根据多对这样的对应关系，计算出一套适用于整张 target 影像的坐标转换规则。

## 2. 仿射变换公式

本项目采用二维仿射变换：

\[
x_s=ax_t+by_t+c
\]

\[
y_s=dx_t+ey_t+f
\]

其中：

- \((x_t,y_t)\) 是 target 中的像素坐标。
- \((x_s,y_s)\) 是转换后对应的 src 像素坐标。
- \(a,b,c,d,e,f\) 是通过控制点求出的 6 个参数。

更通俗地说：

> 输入 target 中某个像素的位置，公式会告诉我们它应该对应到 src 中的什么位置。

### 2.1 六个参数的直观含义

- \(c,f\) 主要控制整张影像的左右和上下平移。
- \(a,b,d,e\) 共同控制缩放、旋转和倾斜。

需要注意，不能严格地将某个参数单独解释为“只负责旋转”或“只负责缩放”。\(a,b,d,e\) 是组合工作的。

可以简单记为：

```text
a、b、d、e：改变影像的大小、形状和朝向
c、f：移动整张影像的位置
```

### 2.2 最简单的纯平移示例

假设 target 整体向右偏了 20 像素、向下偏了 10 像素，校正时就需要向左移动 20 像素、向上移动 10 像素：

\[
x_s=x_t-20
\]

\[
y_s=y_t-10
\]

写成完整形式：

\[
x_s=1x_t+0y_t-20
\]

\[
y_s=0x_t+1y_t-10
\]

因此：

```text
a = 1
b = 0
c = -20
d = 0
e = 1
f = -10
```

将 target 像素 `(120, 80)` 代入：

\[
x_s=1\times120+0\times80-20=100
\]

\[
y_s=0\times120+1\times80-10=70
\]

最终得到：

```text
target (120, 80) → src (100, 70)
```

### 2.3 为什么 x 和 y 会互相影响

如果只有平移或简单缩放，新的横坐标通常主要由原横坐标决定，新的纵坐标主要由原纵坐标决定。

但影像发生旋转时：

- 位于影像上方和下方的点，其横向移动量可能不同。
- 位于影像左侧和右侧的点，其纵向移动量可能不同。

因此，计算新的横坐标时需要同时参考原来的 \(x\) 和 \(y\)，计算新的纵坐标时同样需要同时参考 \(x\) 和 \(y\)。这就是公式中存在 \(by_t\) 和 \(dx_t\) 的原因。

## 3. 如何求出 6 个参数

每一对控制点可以产生两个方程：

\[
x_s=ax_t+by_t+c
\]

\[
y_s=dx_t+ey_t+f
\]

需要求解的未知数共有 6 个，因此：

- 1 对控制点提供 2 个方程。
- 2 对控制点提供 4 个方程。
- 3 对控制点提供 6 个方程。

理论上至少需要 3 对控制点。

对于 \(n\) 对控制点，程序会建立一个 \(2n\times6\) 的方程组，并使用 `numpy.linalg.lstsq` 进行最小二乘求解。控制点超过 3 对时，通常不存在一组参数能让所有点完全无误差地重合，因此最小二乘法会寻找整体误差尽量小的解。

建议实际使用 4～8 对或更多控制点，并尽量分散在影像四周和中心。不要让控制点集中在局部区域，也不要让它们近似位于同一条直线上。

相关实现位于：

- [`solve_affine()`](../logic/registration.py)
- [`align_target_to_src_new_tif()`](../logic/registration.py)

## 4. 如何给 target 像素赋予地理位置

求出仿射参数以后，只能得到 target 像素对应的 src 像素位置，还没有得到真实地理坐标。

完整过程分为两步：

```text
target 像素坐标
        ↓ 仿射变换
src 像素坐标
        ↓ src 的 GeoTransform
地理坐标
```

### 4.1 第一步：target 像素转换为 src 像素

继续使用前面的纯平移示例：

```text
target (120, 80) → src (100, 70)
```

这里的 `(100, 70)` 仍然只是 src 中的像素位置。

### 4.2 第二步：src 像素转换为地理坐标

GeoTIFF 使用 6 个 GeoTransform 参数描述像素坐标与地理坐标之间的关系：

```text
GT = (GT0, GT1, GT2, GT3, GT4, GT5)
```

转换公式为：

\[
X_{\text{geo}}=GT_0+x_sGT_1+y_sGT_2
\]

\[
Y_{\text{geo}}=GT_3+x_sGT_4+y_sGT_5
\]

这 6 个参数可以直观理解为：

| 参数 | 含义 |
| --- | --- |
| `GT0, GT3` | 像素 `(0,0)` 所在的地理位置 |
| `GT1, GT4` | 在影像中向右移动 1 个像素时，地理坐标如何变化 |
| `GT2, GT5` | 在影像中向下移动 1 个像素时，地理坐标如何变化 |

也可以简单记为：

```text
GT0、GT3：整张影像放在哪里
GT1、GT2、GT4、GT5：影像的像元大小、方向和倾斜程度
```

对于常见的正北朝上影像，`GT2` 和 `GT4` 通常为 0。

假设 src 的 GeoTransform 为：

```text
GT = (
    500000,   # 左上角地理 X
    0.1,      # 每个像素宽 0.1 米
    0,
    3500000,  # 左上角地理 Y
    0,
    -0.1      # 每向下一个像素，地理 Y 减少 0.1 米
)
```

将 src 像素 `(100, 70)` 代入：

\[
X_{\text{geo}}=500000+100\times0.1+70\times0=500010
\]

\[
Y_{\text{geo}}=3500000+100\times0+70\times(-0.1)=3499993
\]

因此：

```text
target 像素 (120, 80)
→ src 像素 (100, 70)
→ 地理坐标 (500010, 3499993)
```

这里得到的通常是 src 坐标系下的投影坐标，不一定是经纬度。如果 src 使用 UTM 等投影坐标系，坐标单位通常是米；需要经纬度时还要继续转换到 WGS84。

## 5. 新 GeoTransform 如何得到

GeoTIFF 不会给每一个像素单独保存一组地理坐标。程序会将“target 像素到 src 像素”和“src 像素到地理坐标”两个变换合并，生成 target 输出影像的新 GeoTransform。

完整计算公式为：

\[
NewGT_0=GT_0+GT_1c+GT_2f
\]

\[
NewGT_1=GT_1a+GT_2d
\]

\[
NewGT_2=GT_1b+GT_2e
\]

\[
NewGT_3=GT_3+GT_4c+GT_5f
\]

\[
NewGT_4=GT_4a+GT_5d
\]

\[
NewGT_5=GT_4b+GT_5e
\]

本项目通过矩阵乘法完成同样的计算：

```text
T_new = T_src_geo × T_target_to_src_pixel
```

然后通过 GDAL 将 `T_new` 写入配准输出文件。

### 5.1 正北朝上影像的简化形式

如果 src 满足：

```text
GT2 = 0
GT4 = 0
```

则可以简化为：

\[
NewGT_0=GT_0+GT_1c
\]

\[
NewGT_1=GT_1a
\]

\[
NewGT_2=GT_1b
\]

\[
NewGT_3=GT_3+GT_5f
\]

\[
NewGT_4=GT_5d
\]

\[
NewGT_5=GT_5e
\]

对应关系为：

| 仿射参数变化 | 对 GeoTransform 的主要影响 |
| --- | --- |
| `c、f` | 改变 `GT0、GT3`，即平移 |
| `a、e` | 改变 `GT1、GT5`，即缩放 |
| `b、d` | 改变 `GT2、GT4`，即旋转或倾斜 |

所以，并不是所有配准都只修改 `GT0` 和 `GT3`：

- 如果两张影像只有位置偏移，通常只改变 `GT0、GT3`。
- 如果还存在旋转、缩放或倾斜，`GT1、GT2、GT4、GT5` 也会改变。

## 6. 当前项目实际如何输出配准结果

当前实现的主要步骤是：

1. 检查 src 和 target 控制点数量是否相同。
2. 检查是否至少有 3 对控制点。
3. 求解 target 像素到 src 像素的仿射参数。
4. 读取 src 的 GeoTransform 和投影坐标系。
5. 合并仿射变换与 src GeoTransform，得到新的 GeoTransform。
6. 使用 GDAL `CreateCopy()` 将 target 复制成新的 GeoTIFF。
7. 给输出文件写入新的 GeoTransform 和 src 投影。
8. 为输出文件构建金字塔。

需要特别注意：

> 当前实现不会重新采样 target 的像素数组，而是复制原始像素数据并更新地理参考信息。

因此，它属于“更新地理定位”的配准方式。在 GIS 软件中叠加时，软件会根据新的仿射 GeoTransform 将影像放到相应位置。它并没有把 target 的像素重新计算到与 src 完全一致的规则网格。

如果后续要求：

- 输出影像与 src 的分辨率完全一致；
- 像元行列严格对齐；
- 输出范围和 src 完全相同；
- 消除 GeoTransform 中的旋转项；

则还需要增加一次 `GDAL Warp` 重采样。

## 7. 配准质量检查

### 7.1 训练 RMSE

对于每对控制点，程序计算预测的 src 像素位置与人工点击位置之间的欧氏距离：

\[
error_i=\sqrt{(x'_s-x_s)^2+(y'_s-y_s)^2}
\]

然后计算：

\[
RMSE=\sqrt{\frac{1}{n}\sum_{i=1}^{n}error_i^2}
\]

单位为像素。数值越小，说明控制点上的拟合误差越小。

### 7.2 最大误差

最大误差是所有控制点误差中的最大值，用于发现可能点击错误或匹配错误的控制点。

### 7.3 留一 RMSE

控制点数量不少于 4 对时，程序会：

1. 每次暂时去掉 1 对控制点。
2. 使用其余控制点求解仿射变换。
3. 预测被去掉控制点的位置。
4. 汇总所有被去掉点的预测误差。

相比训练 RMSE，留一 RMSE 更能反映变换对未参与拟合位置的预测能力。

### 7.4 退化与稳定性检查

程序还会检查：

- 方程组的矩阵秩是否小于 6；
- 线性变换部分的行列式 `det(A)` 是否接近 0；
- 条件数 `cond(A)` 是否过大。

当前判断条件包括：

```text
rank < 6      → 控制点分布退化，拒绝求解
|det(A)| < 1e-8 → 变换可能退化成线或点，拒绝输出
cond(A) > 1e8   → 数值条件过差，拒绝输出
```

只有 3 对控制点时，仿射模型可能精确穿过这 3 对点，因此训练 RMSE 可能接近 0，但这并不代表整幅影像的配准误差为 0。

## 8. 配准输出的金字塔处理

配准完成后，程序会对新输出的 GeoTIFF 无条件请求构建以下 5 个轻量 Overview 层级：

```text
[4, 8, 16, 32, 64]
```

采用的重采样方式为 `AVERAGE`，Overview 压缩方式为 `DEFLATE`。

### 8.1 target 已有金字塔时

原始 target 以只读方式打开，不会被修改。输出路径若已存在，程序会先删除旧输出，再通过 `CreateCopy()` 创建一个新文件。

当前 `CreateCopy()` 没有设置：

```text
COPY_SRC_OVERVIEWS=YES
```

而 GeoTIFF 驱动该选项默认为 `NO`，因此 target 原有的 Overview 通常不会复制到输出文件。随后程序会在输出文件中重新计算 5 层轻量 Overview。

所以：

- target 原来有 7 层：原文件仍保留 7 层，输出文件重新计算 5 层。
- target 原来有 5 层：原文件仍保留 5 层，输出文件请求重新计算 5 层。
- target 原来没有金字塔：输出文件同样请求构建 5 层。

最终实际生成数量还取决于影像尺寸和 GDAL 是否成功完成全部层级，但当前代码的目标固定为 5 层。

### 8.2 与“金字塔构建”页面的区别

独立的“金字塔构建”页面采用另一套判断：

```text
只要第一波段的 Overview 数量大于 0，就提示影像已有金字塔并停止。
```

因此，一张已经有 2 层 Overview 的影像，在独立金字塔页面不会自动补齐到 5 层；但通过配准生成新文件时，输出文件会重新请求构建完整的 5 个层级。

相关代码位于：

- [`logic/registration.py`](../logic/registration.py)
- [`logic/pyramid_builder.py`](../logic/pyramid_builder.py)

## 9. 使用建议

1. 至少选择 4 对控制点，条件允许时使用 6～10 对。
2. 控制点应覆盖影像四周和中心，避免集中在一个小区域。
3. 不要选择近似共线的控制点。
4. 优先选择轮廓清晰且两张影像中不易变化的地物。
5. 同一对点必须按相同顺序分别在 src 和 target 中点击。
6. 不要只看训练 RMSE，还应结合最大误差和留一 RMSE。
7. 如果对输出网格有严格要求，应在更新地理参考后增加重采样步骤。

## 10. 总结

控制点图像配准的核心可以概括为：

```text
控制点告诉程序“这些位置应该对应”
        ↓
最小二乘法求出整张图的仿射变换
        ↓
target 像素映射到 src 像素
        ↓
使用 src 的 GeoTransform 获得地理坐标
        ↓
将合并后的新 GeoTransform 写入 target 副本
        ↓
为输出 GeoTIFF 重新构建金字塔
```

一句话总结：

> 本项目通过人工同名控制点建立 target 像素与 src 像素的对应关系，再借助 src 的地理参考信息，为 target 建立新的像素到地理坐标转换规则。
